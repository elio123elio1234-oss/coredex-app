# HW_PLAYGROUND — מתחם מחקר חומרה: ‎3× Lead II על ADS1293

מטרת המתחם: לבדוק האם דגימת Lead II בשלושה ערוצים במקביל + מיזוג סטטיסטי
(ממוצע / חציון / משוקלל) משפרת את איכות האות — על ESP32 + CJMCU-1293
**נפרדים** מהאבטיפוס. צורבים על האבטיפוס רק אחרי הצלחה מוכחת ואישור מפורש.

## מבנה

| תיקיה | תוכן |
|---|---|
| `docs/` | **ADS1293_RESEARCH.md** — המחקר המלא (ניתוב, WCT, RLD, תוכניות A/B/C) · **CJMCU-1293_BOARD_MAP.md** — מפת המודול והחיווט · **OPEN_QUESTIONS.md** — שאלות פתוחות |
| `firmware_current/` | עותק עיון של הקושחה שרצה היום על האבטיפוס (מקור: `Desktop\ESP32-ADS1293-master`) |
| `firmware_playground/` | קושחת הניסויים: 3 ערוצים, פריסטים A/B/C, שליטת רגיסטרים מלאה דרך BLE |
| `gui/` | `index.html` — GUI ‏Web Bluetooth (Chrome/Edge): גלים חיים, מיזוג, סטטיסטיקת רעש, קונסולת רגיסטרים, הקלטת CSV |
| `flashing/` | `FLASHING.md` — הוראות צריבה (על ה-ESP הנוסף בלבד) |

## TL;DR של המחקר

- 6 פיני כניסה, **3 ערוצי מדידה** — כל ערוץ בוחר זוג פינים בתוכנה; אותו פין
  יכול לשמש כמה ערוצים → "3× Lead II מול RA אחת" נתמך בחומרה כמות שהיא.
- **אין חיסור WCT נסתר** — ערוץ מודד INP−INN נטו; Wilson כבוי כברירת מחדל.
- **אין פין RLD על השקעים** — אבל RLD מנותב פנימית לכל IN דרך רגיסטר
  `RLD_CN`. בפריסט A הוא מקבל סוף-סוף אלקטרודה ייעודית (IN6) — שיפור לעומת
  היום, שבו הוא רוכב על אלקטרודת ה-LL.
- הכול שינויי רגיסטרים בלבד. שום מגע בחומרה.

## זרימת עבודה

1. לחווט את ה-ESP הנוסף (ראה `flashing/FLASHING.md` שלב 0).
2. לצרוב את `firmware_playground` (שלבים 1–3 שם).
3. לפתוח `gui/index.html` ב-Chrome → להתחבר → לבחור פריסט → להקליט CSV.
4. להשוות σ רעש/מורפולוגיה בין פריסטים ומצבי מיזוג.
5. הצלחה → החלטה משותפת → שילוב באבטיפוס (דרך `CYPHIX_SHARED` קודם!).

> המתחם הזה הוא סביבת מחקר: פרוטוקול ה-BLE שלו (UUIDs חדשים, שם
> `CYPHIX-PLAYGROUND`) נפרד בכוונה מפרוטוקול הייצור, כדי שאפליקציות CYPHIX
> לא יתבלבלו. קידום לחוזה ייצור = הוספה ל-`CYPHIX_SHARED` תחילה (כלל §2.1).
