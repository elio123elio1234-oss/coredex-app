# PARITY.md — Web ↔ iOS ↔ Android feature ledger

**This file is mandatory bookkeeping for the Cross-Platform Rule (root
`CLAUDE.md` §1).** Every feature that exists on any platform has a row here.
A feature shipped web-only gets a row marked `pending` with a reason —
"we forgot" must be structurally impossible.

Legend: `✅ done` · `🟡 partial` · `⏳ pending` · `🔬 needs-iOS-verify` (built
but never run on a physical iPhone — Windows dev machine, see root §5) · `—` n/a.

## Onboarding / auth (v0.19.0 — from the "CYPHIX Onboarding" design reference)

The signed-out experience. It stands in FRONT of the navigator (`AuthGate`), so
none of the tabs mount until there is an account. The web has the same flow in a
different shape (`AuthPage` + `RegisterWizard`); the mobile one follows the
design reference the user supplied, and the rows below say where the two part
company.

| **Splash** | ⏳ (web boots straight into its gate) | 🔬 | 🔬 | NAVY screen, in both themes: the full `BrandLogo` (mark + CYPHIX + "MEDICAL") fading up, then the tagline. Its width is **90 % of the window capped at 520**, drawn with the new `crop` — a fixed point size is a guess that is right on exactly one screen. ⚠️ **TRAP (v0.19.5): an inherited viewBox is not necessarily tight around its artwork.** `BrandLogo`'s ink measures x 41.34 → 181.45 inside a box declared 34 → 209 — 7.3 units of air on the left against 27.6 on the right — so centring the BOX put the artwork ~18 pt left of centre and filled only 80 % of the width it claimed. Real lockup width went 256 → 351 pt on a standard iPhone. ⚠️ **v0.19.4 REVERTED v0.19.3**, which had made this a WHITE screen carrying a mark-only `CyphixLogo`: three things changed when only the size was the complaint. `CyphixLogo` is deleted rather than left uncalled — three lockups with two callers is how the wrong one gets picked later (`git show 542a650`). ## Traps this port has already paid for twice — do not reintroduce

| Trap | What happens | Rule |
|---|---|---|
| `StyleSheet.absoluteFill` on an `<Image>` with `resizeMode="contain"` inside an `overflow: hidden` parent | The Image takes its box from four zero insets with no intrinsic size, `contain` resolves against the wrong frame, and the parent crops the photo to a corner — the patient sees one finger. Broke `LimbPrep` in v4.0.0 and again in v0.10.0 | Pass explicit point `width`/`height`. Use `position: 'absolute'` for stacking only |
| Deriving a visual from "what the real thing looks like" | v0.10.0 painted the report strips on pink clinical ECG paper. CYPHIX's sheet is white with a blue grid (`--ecg-*` in `report.css`) | The web is the reference for anything on a brand surface. Read the token, do not reason about the domain |
| Two writers of the iOS orientation API | Three rotations per navigation (v0.8.0 post-mortem in `RootNavigator`) | react-native-screens only — route `orientation` or `navigation.setOptions`. `lockAsync` is banned |
| ★ Reading "the feature doesn't work" as "the feature is broken" | "There is only a demo signal, never the real hardware" sounds like a defect in the ECG path. Every part of that path was correct — both native modules, the frozen contract, the raw buffer, the display filter, the analysis on raw — and so was the firmware. The cause was the **environment**: Expo Go contains no `cyphix-ble`, so `requireOptionalNativeModule` returns null and the documented simulator fallback engages. Hours can be spent debugging a pipeline that was never wrong | Before debugging a feature, establish that the code under suspicion is **running at all**. An optional native module is null in Expo Go by design; a fallback doing its job looks exactly like a failure. Ask "which build is this?" first |
| A permission declared in the manifest and never requested | `BLUETOOTH_SCAN`/`BLUETOOTH_CONNECT` sat in `app.json` since the module was written, so it read as done. Nothing called for them at runtime, and Android's `startScan` then returns **no results and no error** — identical on screen to the device being absent or off. The PARITY row said Android ✅ | A manifest entry is a request for permission to ask, not a grant. Any Android capability behind a dangerous permission needs a runtime request at the call site — and a silent-empty API is worse than a throwing one, so treat "found nothing" as a permission suspect first |
| Rasterising a logo by eye instead of from its path | An icon hand-traced to look like `BrandLogo` is a second, unlinked copy of the brand: the day either changes, they diverge, and nobody notices because both look right in isolation | Render from the real path data (`scripts/make-icons.js` copies `BrandLogo`'s verbatim). Regenerating is a command, not a redraw |
| Stepping a size on a threshold | An 89 pt lead card drew a TALLER trace than a 92 pt one, so traces shrank as the layout grew | Scale continuously, and round dead margin DOWN |
| A `<Text>` in a `flexDirection: 'row'` | Does not wrap — it overflows its parent and prints through the border. Word-valued metrics ("Slightly variable") escaped their tiles in v0.11.0 | `flexShrink: 1` on anything that can be long, `flexShrink: 0` on the unit beside it |
| Porting a **print** layout element-for-element | The report's two A4 sheets became a repeated letterhead and six 51 pt slivers on a phone. Every element was faithful; the result was a fax (v0.11.0) | Root §3.3 is two halves: brand identity is identical, **layout follows the platform**. Ask what the layout is solving for — a printer is not a thumb |
| One `<Svg>` wider than the GPU's texture limit | react-native-svg gives each `<Svg>` a single native texture. Past ~4 096 px it draws **nothing** — a blank lead that looks like missing data, not like a rendering bug. A zoomed 10 s sheet is 6 600 px on a 3× phone | Tile the paper (`EcgReviewStrip`), and keep `TILE_MM` a multiple of the 5 mm major grid or every seam shows as mismatched squares |
| Porting a **hover** interaction to a finger | The web caliper is hover → click → click. A fingertip is ~9 mm — 360 ms of paper at 25 mm/s, wider than a QRS — so an absolute-positioned touch tool measures whatever is under the hand and therefore invisible | Persistent handles, dragged by **delta** not to absolute position, so the thing being positioned stays beside the finger. Precision comes from zoom |
| **A `PanResponder` inside a `ScrollView` that claims on MOVE** | It never gets the gesture. A ScrollView that has begun panning OWNS the responder and a child asking afterwards is ignored — so in v0.15.0 grabbing a caliper crosshair scrolled the paper underneath it, and **not one draggable thing in the History viewer worked**. Every green check passed | Claim on **touch-down** (`onStartShouldSetPanResponder` + capture) and set `scrollEnabled={false}` from `onPanResponderGrant`, so the scroll never begins |
| **`options.tabBarButton` on a navigator with a custom `tabBar`** | Standard advice for animating tab items is a custom `tabBarButton`. It is consumed **only by React Navigation's own `BottomTabBar`**. `RootNavigator` passes `tabBar={}`, which replaces the whole bar, so setting `tabBarButton` here reads as configuration and does exactly nothing — including in a code review, which is the dangerous part | Before taking a navigator recipe, check which layer it plugs into. With `tabBar={}` the equivalent of a custom button is a child of your own bar (`DockItem`), and the `options` route is closed |
| ★ **An indicator defined relative to the surface under it** | The dock's selection pill was a translucent white. It was never visible in its own right — it was visible *because it was brighter than the bar*. One release later the same change set made the bar glassier to look more like the system's, the pill lost the only thing it contrasted against, and **the current tab stopped being marked at all**. The dock's own dressing destroyed the one thing the dock exists to show, and typecheck, both bundles and `expo-doctor` all passed while it did — none of them can see contrast | Anything that says "you are here" must be legible **on its own terms**, because the surface beneath it is the part most likely to be restyled. Make it solid, and where two values are *required* to match (here: the pill and the cut-outs in the icon standing on it) make them literally **one constant** — "similar" drifts, one value cannot |
| **A prop named for one branch of a two-branch component** | `GlassSurface` picks Liquid Glass on iOS 26+ and a tinted BlurView everywhere else. The colour prop was called `fallbackTint` and was passed only to the second branch, "because Liquid Glass tints itself". It does not: untinted `regular` glass over a LIGHT page is nearly clear, so on an iPhone every sheet, the dock, the report bar and the confirm dialog rendered with **no background at all**, while the identical code on a Galaxy looked exactly right. Found by holding the two phones side by side | Name a prop for what it MEANS, not for the branch that happened to need it first (`tint`, not `fallbackTint`). And when a component resolves to per-platform implementations, check that every input reaches every one of them |
| **A gate that opens the instant the state it watches flips** | Registration writes the account, so `auth.user` exists ONE SCREEN BEFORE the flow is over — and `AuthGate` swapped the whole flow for the app on that frame. "Profile created" was written, styled, animated and **structurally unreachable**; the patient would have gone from the review screen straight to the tabs. `tsc`, both bundles and `expo-doctor` were green | A gate needs the state AND permission to act on it. `authSlice.justRegistered` is that permission, and `welcomeAcknowledged` is the patient handing it back. Ask of any gate: is there a screen that lives on the far side of the condition? |
| A percentage grid with `gap` | `gap` is not part of the percentage, so three 33 % keys plus two 10 pt gaps overflow the row — and `flexWrap` answers by silently giving a **two-column dialler**. Same arithmetic would have put the eighth blood-type tile on its own line | Size the cells UNDER the fraction (30 % for thirds, 20 % for quarters) and let `flexGrow` hand the slack back |
| `paddingEnd` / `end` in an app that does not switch `I18nManager` | They resolve against the NATIVE layout direction, not the app's chosen language. This app draws RTL itself (see `i18n/I18nProvider`), so `end` stays the right edge in Hebrew while the control it was clearing moves left — and the text runs underneath it | Explicit `left`/`right`, chosen from the `rtl` flag the translation hook already gives every component |
| A handle that must also be TAPPABLE | Owning touch-down swallows any `Pressable` inside it — a marker that drags perfectly and cannot be opened. Claiming on move instead trades one broken half for the other | Own the gesture, and tell tap from drag **on release, by travel** (`< TAP_SLOP` = tap). One target, both behaviours |
| ★ **A `PanResponder` rebuilt MID-GESTURE** | Its handlers close over the running totals (`last`, `travelled`) that convert "distance since touch-down" into "distance since the last event". `useMemo(…, [onTap, onStep])` rebuilds it between move events, because callback props are fresh arrows every parent render and every drag re-renders the parent. Result: each move applies the FULL distance (the thing runs away from the finger) and release reads travel 0 as a TAP. On a reference line that meant drag → lift → **it deleted itself** (v0.16.0) | Build the responder ONCE (`useMemo(…, [])`) and read everything live through a ref — `useDragHandle` in `EcgReviewSheet`. **Never put a callback prop in a responder's dependency array** |
| A landscape screen that ignores the safe area | The notch / Dynamic Island is on a SIDE in landscape, not the top. A full-bleed sheet put the first ~50 pt of every ECG lead under it — a cut-off clinical trace, not a cosmetic gap | Inset all FOUR edges on any landscape route, and keep floating chrome out of the content's own box |
| An invisible drag surface | Compare's ghost was moved by dragging anywhere on the sheet, with nothing on screen saying so. It was reported as "compare does not work" — which, as a feature, it did not | If a gesture is the only way to use something, draw the handle. A labelled affordance is the feature; the gesture is just how it is operated |
| Giving a tool's chrome the same weight as the trace | v0.15.0's labelled 44 pt chips + headline + meta + tabs + hint took ~a third of the screen from a waveform. Every element was justifiable on its own | On a phone, chrome competes with the SUBJECT, not with other chrome. Icons where the pictogram is honest, a labelled sheet where it is not, a FIXED-height status slot that tools share rather than add to, and a landscape full-screen for when the content's aspect is not the phone's |
| ★ **Presenting an overlay in a `Modal`** | A `Modal` is a SEPARATE WINDOW — its own `UIViewController` on iOS, a `Dialog` with its own `Window` on Android. Two failures follow, and both shipped. (a) `UIVisualEffectView` samples **its own window's** layer tree and dimezis' `BlurView` snapshots **its own decor view**; inside a Modal that is empty, so every "glass" sheet in v0.17.0 rendered as a flat grey rectangle — the exact thing it was written to replace. (b) `Modal` defaults to `supportedOrientations={['portrait']}`, so presenting one while the app is landscape makes UIKit raise `UIApplicationInvalidInterfaceOrientation` — an uncaught ObjC exception, so the **process dies**. Tapping MARK in full screen killed the app | Present overlays **in tree** (`components/atoms/OverlayLayer.tsx`). A material needs something behind it, and a Modal is defined by having nothing behind it. `supportedOrientations` only silences (b) and leaves (a) — it is not the fix. Whatever leaves `Modal` must take over its back button, its keyboard handling and its mount lifecycle |
| An overlay hosted inside a **padded** container | Absolutely-positioned children are laid out against the parent's CONTENT box, so a full-screen scrim inside a safe-area-padded root stops at the inset and leaves four unblurred strips | Put the safe-area padding on an inner view and keep the overlay a sibling of it, at the unpadded root |
| ★ **An inline object prop passed to a `memo`-wrapped component** | `palette` was rebuilt on every render of `StudyViewerScreen` and handed to six `memo`-wrapped `EcgReviewStrip`s. The memo never held **once**, so every re-render — a sheet opening, a caliper nudge, one frame of a drag — re-ran `buildEcgPath` over four tiles × six leads, doubled with a ghost. Reported as "it flickers", "it isn't smooth", "feels dated". Two separate rounds of animation tuning chased it and neither helped, because the animation was never the cost | `memo` is a contract with the CALLER. When wrapping a component in it, audit every prop for referential stability and memoise the objects and arrays at the call site — an unstable prop does not weaken the memo, it deletes it. Chase a smoothness complaint by asking what runs on the same frame, not by shortening the animation |
| Re-deriving a signal when the change was a **transform** | Dragging the ghost re-entered `useOverlayRecording` per touch event, allocating six shifted `Float32Array`s and, in warp mode, re-running `alignByFiducials` on all six leads — the most expensive routine in the module, at touch frequency | A translation of an already-computed curve is a transform, not a recomputation. Apply it at DRAW time (`<G translate>` in `EcgReviewStrip`, in the viewBox's millimetres). ⚠️ Tiled paper only draws the samples on each tile, so a translate opens a seam gap unless each tile over-draws by the clamp limit — hence `GHOST_NUDGE_LIMIT_MM`, which is a drawing constraint and not a preference |
| Gating an invisible touch surface on **mode alone** | Clearing the comparison left `mode` on `'ghost'`, so the drag capsule stayed on screen with no ghost — and the full-sheet invisible drag surface under it stayed too, swallowing every touch and freezing the scroll. The visible symptom was a stray capsule; the real one was a dead sheet | Gate on the DATA the mode acts on, not just the mode (`mode === 'ghost' && ghost`), and reset the mode when its subject disappears. Do both: either alone is luck. Anything that covers the screen invisibly must be impossible to leave mounted |
| Stacking two blurs, and animating the outer one's opacity | Reported as "slow, and it flickers a bit when it opens". A `UIVisualEffectView` **re-computes its effect whenever its opacity changes**, so fading a full-screen blur in re-renders it every frame; and Android's `dimezisBlurView` is experimental and snapshots a view tree per frame, so two of them stack that cost. The panel's own glass was sampling a scrim that was itself sampling the page | **One** blur per overlay, on the panel, and never the thing whose opacity animates. Dim the scrim with a plain colour — free on the native driver. This is also what the platform does: an iOS sheet dims its backdrop and reserves the material for the sheet |
| Replacing a **direct-manipulation** gesture with buttons | v0.18.0 answered "compare is not intuitive" by moving the ghost with 40 ms arrow steps in a sheet. Reported immediately as wanting the on-screen drag back. Aligning two heartbeats is judged continuously **by eye**, and no amount of discoverability survives making the reader look away from the trace to press a button beside a list | Buttons cannot substitute for a gesture whose value is the closed loop between eye and hand. When such a gesture is undiscoverable, **draw the affordance over it** — do not replace it. Show the resulting number on screen, so nothing has to be reopened to read it |
| Explaining a feature by listing its **settings** | Compare shipped as filter/alignment rows before anything had said what the grey trace was. Reported twice as "still not clear how to use it" — v0.17.0 answered the wrong half by making the *drag* visible, when what was missing was the *feature* | Lead with what the thing IS (a sentence and a legend), then what it acts on, then how to operate it. And give any gesture-only control a tap equivalent: a drag is the best way to operate something and the worst way to discover it exists |
| Running `npx expo install` from the wrong directory | The legacy global `expo-cli` resolved `latest` into `CYPHIX_SHARED`, pulling expo 57 + RN 0.86 into a package that has no dependencies at all, and would have broken the Expo Go SDK 54 pin (`CLAUDE.md` §1) had it landed in the app | `Set-Location` to the project explicitly, and check the installed version against `expo@54`'s `bundledNativeModules.json`, never against npm `latest` |

## Open verification debt

- Everything marked 🔬 was built on Windows and has **never run on an
  iPhone**. Per root `CLAUDE.md` §5, do not claim iOS works until it has run
  via Expo Go (UI only) or an EAS dev build (native BLE included).
- ★ **The whole native BLE path is unrun.** `CyphixBleModule.swift` has never
  executed once — not against hardware, not at all — because until v0.23.0
  there was no way to get a build containing it onto a phone. `IPHONE_SETUP.md`
  §6.3 lists the four checks that distinguish a real trace from a convincing
  one: take the fingers off the electrodes (a demo keeps beating), light
  exertion, a held breath, and backgrounding the app (the trace must **stop**
  and mark itself not-live — that is the v0.23.0 watchdog). Until someone has
  done those, "the hardware works on iOS" is unproven.
- The staleness watchdog is verified only by construction. A real screen lock,
  a real walk out of BLE range and a real ESP32 brown-out have not been tried,
  and those are the events it exists for.
- The new icons have not been seen through iOS's own squircle mask or an
  Android launcher's adaptive crop, which is where icon sizing actually fails.
- The Swift and Kotlin packet parsers duplicate `parseEcgPacket()` by hand.
  If the packet format ever changes, all three must change together —
  consider a shared test vector fixture before clinical use.

- **The v0.19.2 glass fix is inferred, not observed.** The symptom (invisible
  on iOS 26, correct on Android) and the API both point one way, but this
  machine cannot run iOS. It wants one look at the sign-out dialog and one at a
  History sheet on the iPhone.

- **The v0.24.0 dock interaction is still unverified on any handset.** One of
  its three judgement calls has since been settled *by* a handset —
  `isInteractive` on the whole bar was reported as "no glass effect at all" and
  is out (v0.24.1). Two remain:
  1. The **swell against `overflow: hidden`** is computed, not seen: at
     `HOLD_SWELL` the pill grows to 60.0 pt inside a 65.1 pt inner box, and
     horizontally to ~4.5 pt short of the rounded cap on the outermost tabs.
     It should press against the container without being cut by it.
  2. Whether the highlight **travelling on touch-down** reads as responsive or
     as jumpy.

- **The dock cannot look like Apple Music's bar while nothing passes under it.**
  A material refracts what is behind it; Apple Music's tab bar reads as glass
  because artwork and lists scroll *under* it. This dock floats over a soft flat
  backdrop, so however the tint is tuned it can only render as a translucent
  plate. Fixing that properly means letting screen content run beneath the dock
  rather than stopping at `dockFootprint()` — a layout change to every patient
  screen, not a dock change, and not attempted here.

- **The welcome scrim (v0.19.1) was judged against a thumbnail.** Whether
  white type is comfortable over that photograph at those four gradient stops
  is a daylight-and-a-real-screen question, not a code question.

- **The whole onboarding flow (v0.19.0) is unverified on any device.** It
  typechecks, both platforms bundle and `expo-doctor` passes — which, per root
  `CLAUDE.md` §6.4 and the Scan History history below, proves only that it is
  well-formed. Specifically unproven: the four ported animations at real
  frame rates, the numeric pad and the OTP boxes on a SHORT phone (both steps
  scroll for exactly that reason, and nobody has watched them do it), the
  slider under a real thumb, `expo-image-picker` returning a usable square,
  and — untestable on Windows at all — Face ID.

- **Scan History has been through three rounds of device feedback** (v0.16.0,
  v0.17.0, v0.18.0) and sixteen findings. Every round passed `tsc`, both
  `expo export`s and `expo-doctor` before the phone found them — including a
  hard native crash and a blur that was never going to render. That is the
  clearest evidence in this repo for why §6.4 says what it says.
- v0.17.0's claim that the sheets rise on a blurred material was **wrong**: they
  were in a `Modal`, so they could not. Corrected in v0.18.0's entry.
- v0.18.0's own fixes are **partly confirmed on device**: the sheets now look
  right and full screen no longer crashes. Its blurred scrim was **too slow**
  and its arrow-pad answer to compare was **rejected** — both corrected in
  v0.18.1.
- **The viewer was measurably slow and nobody could see it from Windows.** Three
  device rounds reported "flickers", "not smooth", "feels dated" before the cause
  was found: one un-memoised object prop. Treat every future smoothness report as
  a question about what runs on the frame, not about the animation.
- Still **untested**: whether the memoised strips and the transform-based ghost
  drag are now smooth in the hand, whether the tiled ghost shows any seam at the
  clamp limit, whether one blur is now smooth enough on a real Android
  build (`expo-blur` behaves differently per OEM), whether the sheet clears the
  keyboard now that `OverlayLayer` and not the OS is lifting it, and whether
  Android's back button closes a sheet rather than the screen.
- Still untested from v0.17.0: the once-built responder, and the tap-vs-drag
  threshold (6 pt — possibly too tight for a shaky hand).
- The portrait toolbar is now **seven** 44 pt tools. It computes to 364 pt,
  which fits a 375 pt screen with 11 pt to spare; that margin has never been
  seen on a small device.
- The **tiled sheet's seams** at every zoom level, and whether the caliper
  crosshair lands where the finger expects, remain untested at the extremes.
- The **PDF has never been printed**. It bundles and the geometry comes from
  the shared builders, but page breaks, margins and how a printer renders
  0.1 mm grid strokes are only knowable on paper.
