# CLAUDE.md — CYPHIX Platform · Cross-Platform Constitution (root)

> This is the **root source of truth** for the whole CYPHIX platform:
> Web + iOS + Android + Server + Shared. It governs everything that crosses
> a project boundary. Each sub-project keeps its own `CLAUDE.md` for its
> internal rules; **this file wins on any cross-platform question.**
> If a request conflicts with a rule here, stop and flag it before coding.

---

## 0. Repository map (who lives where)

```
Coredex_App/                     ← LEGACY static HTML/JS app. READ-ONLY reference.
├── CLAUDE.md                    ← THIS FILE (cross-platform constitution)
├── CYPHIX_MEDICAL_WEB/          ← React 18 web app (own nested git repo, own CLAUDE.md)
├── CYPHIX_SERVER/               ← Fastify + Postgres API (Docker), /api/v1
├── CYPHIX_SHARED/               ← ★ Single-Source-of-Truth TS package (no UI, no build step)
└── CYPHIX_MEDICAL_MOBILE/       ← React Native (Expo) app → iOS + Android from ONE codebase
    ├── ios/       (generated by `npx expo prebuild` — Swift native modules live in modules/)
    ├── android/   (generated by `npx expo prebuild` — Kotlin native modules live in modules/)
    └── modules/cyphix-ble/      ← native BLE bridge: Swift (CoreBluetooth) + Kotlin (BluetoothGatt)
```

- The legacy `Coredex_App` root files (`index.html`, `js/`, `css/`, `models/`,
  `worker.js`) are **frozen reference material — never modify them.**
- `CYPHIX_MEDICAL_WEB` is **its own nested git repo** with its own remote and its
  own ship-on-every-change rule (§8A there). Never draw conclusions about its git
  state from the parent repo.
- One mobile project serves BOTH platforms. There is deliberately **no separate
  `CYPHIX_MEDICAL_IOS` / `..._ANDROID` codebase** — platform differences are
  expressed inside `CYPHIX_MEDICAL_MOBILE` via `Platform.OS`, platform file
  suffixes (`.ios.ts` / `.android.ts`), and the Swift/Kotlin halves of each
  native module. Two UI codebases would guarantee drift; the Cross-Platform
  Rule below would be unenforceable.

## 1. ★ THE CROSS-PLATFORM RULE (the reason this file exists) ★

**Every feature, screen, button, or behaviour added to the Web app MUST be
translated and added to the iOS app and the Android app — no exceptions,
in the same change set or an explicitly tracked follow-up.**

Concretely, a feature is **not done** until this checklist passes:

- [ ] Web: implemented per `CYPHIX_MEDICAL_WEB/CLAUDE.md`.
- [ ] Mobile: the same feature exists in `CYPHIX_MEDICAL_MOBILE`, reachable
      from navigation, working on **both** iOS and Android.
- [ ] Any new data shape / endpoint / protocol constant was added to
      `CYPHIX_SHARED` **first**, and all consumers import it from there.
- [ ] Parity ledger updated: `CYPHIX_MEDICAL_MOBILE/PARITY.md` has a row per
      feature with columns `Web | iOS | Android | Notes`. A feature that ships
      web-only gets a row marked `pending` — silence is not allowed.

If a change genuinely cannot apply to a platform (e.g. Web Bluetooth quirk),
write **why** in `PARITY.md`. "We forgot" must be structurally impossible.

## 2. Single Source of Truth (what is shared, and where)

### 2.1 `CYPHIX_SHARED` — the platform-neutral core

Pure TypeScript, **zero React / zero DOM / zero React Native imports**.
Consumed as source by Vite (web) and Metro (mobile) via the `@cyphix/shared`
alias. Rule of thumb: *if a file would work in Node with no polyfills, it can
live in shared; otherwise it cannot.*

Lives there (and ONLY there — never fork a copy):

| Concern | Module |
|---|---|
| BLE wire protocol: UUIDs, 320 Hz, packet parser (5 B / 9 B strides), rail detection constants | `src/ble/` |
| ECG domain types (`EcgBufferView`, leads, recordings, validator shapes) | `src/types/ecg.ts` |
| API contract: endpoint paths, request/response types, the `{ url, method, body }` / `{ status, message }` envelope | `src/api/` |
| Domain constants (sample rate, buffer sizes, lead order, colours-per-lead) | `src/constants/` |
| Pure business logic (formatters, mappers, protocol helpers) | `src/logic/` |

**Adding an endpoint or domain type directly inside web or mobile is a
violation.** Define it in `CYPHIX_SHARED`, then consume it on every platform.
(The web app predates this package; migrating its existing duplicates into
shared is allowed and encouraged, but must ship per web's own release rules.)

### 2.2 API & Server — one communication layer

- **All** platforms speak to `CYPHIX_SERVER` at `/api/v1` with the same
  bearer-token auth, the same single-flight 401→refresh→retry policy, and the
  same error envelope `{ status, message }` (see web's `httpBaseQuery.ts` —
  the mobile twin must keep behavioural parity with it).
- State/data layer on every platform: **Redux Toolkit + RTK Query**. Endpoint
  definitions mirror each other 1:1; the transport (`fetch` vs RN fetch) is
  the only platform-specific part.
- Realtime (future): one WebSocket contract, defined in `CYPHIX_SHARED`,
  consumed identically everywhere.

### 2.3 Signal processing & AI — equal results on every platform

- The ECG DSP chain (Einthoven derivation, 0.5–40 Hz + 50 Hz notch biquads,
  Pan-Tompkins) is **frozen maths** (see web CLAUDE.md §6.0). Any port to
  mobile must be **numerically identical** — same coefficients, same
  constants. Never "re-tune per platform".
- AI inference runs in exactly one of two sanctioned modes, chosen per
  feature and recorded in `PARITY.md`:
  1. **Server-side (default):** device sends data via the shared API; the
     server runs the model; all 3 platforms get the same answer from the
     same endpoint.
  2. **On-device:** the same `.onnx` artifact runs via `onnxruntime-web`
     (web) / `onnxruntime-react-native` (mobile), always **off the UI
     thread** (Web Worker / native thread), behind one shared TS interface
     in `CYPHIX_SHARED` so callers cannot tell which platform they're on.
- The ONNX model files and `worker.js` are **frozen artifacts** — copy
  byte-for-byte, never edit (web CLAUDE.md §6.1 applies platform-wide).

### 2.4 Business logic vs UI

- Business logic lives in **services + hooks**, never in components — on
  every platform. A React component (web) or RN component (mobile) renders
  props and calls hooks; the hook calls the service; the service uses shared
  types. If logic is UI-independent, push it down to `CYPHIX_SHARED`.

## 3. Mobile architecture (`CYPHIX_MEDICAL_MOBILE`)

### 3.1 Stack (do not swap without approval)

| Concern | Choice |
|---|---|
| Framework | React Native via **Expo SDK** (prebuild / CNG — `ios/` & `android/` are generated, native code lives in `modules/`) |
| Language | TypeScript strict |
| State | Redux Toolkit + RTK Query (same as web) |
| Navigation | **React Navigation, native stack** + bottom tabs |
| Animation | `react-native-reanimated` (UI-thread, 60/120 fps) |
| ECG rendering | `@shopify/react-native-skia` — waveform drawing OFF the JS thread |
| Haptics | `expo-haptics` on every meaningful tap |
| Fonts | System fonts: San Francisco (iOS), Roboto (Android). No custom font unless the brand demands it |
| BLE | **Native module** `modules/cyphix-ble` — Swift/CoreBluetooth + Kotlin/BluetoothGatt (Expo Modules API ⇒ compiled native bridge). **Never a JS-thread BLE polyfill.** |
| On-device AI (future) | `onnxruntime-react-native` in a dev build |

### 3.2 Real-time safety rules (SaMD-grade)

- **The JS thread never touches per-sample ECG data.** BLE notify → native
  ring buffer (Swift/Kotlin) → batched, throttled events to JS (≤ 30 Hz for
  UI state) + direct buffer reads for the Skia renderer. Latency-critical
  paths (waveform, HR) must keep working while JS is busy.
- The 320 Hz / packet-format / DSP constants come from `CYPHIX_SHARED` and
  are as frozen on mobile as on web.
- App-lifecycle honesty: on background/lock, streaming state must be marked
  stale — never render a frozen waveform as live (same principle as web's
  `FRAME_STALE_MS` watchdog).

### 3.3 Native feel (Cupertino vs Material)

- Brand identity (logo, navy palette `#0D2041`/`#0A2540`, tone) is identical
  to web. **Navigation patterns are not:** the web sidebar becomes a
  **Bottom Tab bar** on mobile; back gestures, transitions, headers follow
  each platform's conventions via native stack defaults + `Platform.OS`.
- Same five modules as the web nav, same order, same feature flags:
  Live Scan · Measure · History · Patients · Settings.
- Patient-facing screens follow the web UX law: elderly-simple, fits without
  scrolling, big targets. History stays doctor-oriented.

### 3.4 Compliance carries over

Web CLAUDE.md rules that are platform-independent apply verbatim on mobile:
FHIR R4 typing, RBAC guards, audit logging, data minimization in props,
fictitious PII only, async always modeled (`idle|loading|success|error`),
one component per file, version footers, and a visible version badge.
Secrets: never in the repo; on device use secure storage (Keychain /
Keystore via `expo-secure-store`), never `AsyncStorage`, for tokens.

## 4. Workflow rules

- **Which CLAUDE.md?** Working inside `CYPHIX_MEDICAL_WEB` → its CLAUDE.md
  (including its ship-every-change §8A). Inside `CYPHIX_MEDICAL_MOBILE` or
  `CYPHIX_SHARED` or `CYPHIX_SERVER` → this file + that project's docs.
  Cross-cutting features → this file first.
- A change to `CYPHIX_SHARED` is a change to **three apps**: typecheck web
  AND mobile before calling it done.
- Never edit generated `ios/` / `android/` folders by hand — they are
  disposable (`npx expo prebuild --clean` recreates them). Native code
  belongs in `modules/*/ios` and `modules/*/android`, config in `app.json`
  / config plugins.
- Mobile version badge + `CHANGELOG.md` in the mobile repo mirror the web
  convention.

## 5. Emulators & devices (Windows dev machine — read this before "it doesn't run")

- **Android:** install Android Studio → Device Manager → create a Pixel AVD
  → `npm run android` (or `npx expo start` and press `a`). Works fully on
  this Windows machine, including native modules via a dev build
  (`npx expo run:android`).
- **iOS Simulator does NOT exist on Windows.** Xcode is macOS-only. The
  sanctioned paths to see the app on iPhone from this machine:
  1. **Expo Go on a physical iPhone** (fastest): `npx expo start` → scan the
     QR with the iPhone camera (same Wi-Fi). UI/navigation/API all work;
     the native BLE module is mocked in Expo Go (see §3.1 fallback).
  2. **EAS Build (cloud Macs):** `npx eas build --profile development
     --platform ios` builds a real dev client with the Swift BLE module on
     Expo's servers; install via QR/TestFlight. Requires an Apple Developer
     account for device installs.
  3. A physical Mac (borrowed/CI) for `npx expo run:ios`.
- Never claim an iOS feature "works" from Windows alone — mark it
  `needs-iOS-verify` in `PARITY.md` until it ran on an iPhone.

## 6. ★ EVERY CHANGE IS DOCUMENTED AND PUSHED — no exceptions ★

**Standing instruction from the user. Do this without being asked, on every
change set, in every sub-project.** A change that is not written down cannot
be reviewed, and a change that is not pushed does not exist — if this machine
dies, it never happened.

### 6.1 The documentation trail (all four, every time)

| Artifact | What goes in it |
|---|---|
| `src/config/version.ts` | `APP_VERSION` bumped + `APP_BUILD_LABEL` saying what actually changed — not "updates". This is what renders in the visible badge, and it is how the user tells whether their change is live. |
| `CHANGELOG.md` | A dated entry at the top explaining **why**, not just what. If a previous entry claimed something that turned out to be wrong, say so plainly in the new one. |
| Version footer | Last line of **every file touched**: `// vX.Y.Z — <what this file does / last change>`. |
| `PARITY.md` (mobile) | A row per feature, `Web / iOS / Android`. Anything web-only is `pending`; anything built on Windows but never run on an iPhone is `🔬 needs-iOS-verify`. **A deliberate divergence from web gets a row saying so and why** — silence is not allowed. |

Version numbering: patch for a fix, minor for new behaviour or anything
user-visible, major only when asked.

### 6.2 Where each project pushes

| path | its own repo? | remote |
|---|---|---|
| `Coredex_App/` (parent) | yes | `coredex-app.git` — the legacy app **plus** `CYPHIX_MEDICAL_MOBILE/`, `CYPHIX_SHARED/` and this file |
| `CYPHIX_MEDICAL_WEB/` | **yes, nested** | `cyphix-medical-web.git` — see its own §8A |
| `CYPHIX_SERVER/` | **yes, nested** | its own |
| `CYPHIX_MEDICAL_MOBILE/` | no | lives in the parent repo |
| `CYPHIX_SHARED/` | no | lives in the parent repo |

> ⚠️ **The nested-repo trap.** From the parent, `git status` reports
> `?? CYPHIX_MEDICAL_WEB/` and `git ls-files` on it returns 0. That is NOT
> evidence it is uncommitted — it is just how an outer repo sees a nested one,
> and it has full history. **`cd` into the sub-project first**, then run git.
> Never stage `CYPHIX_MEDICAL_WEB/` or `CYPHIX_SERVER/` from the parent.

### 6.3 Rules

- **Never `git add .` or `git add -A`.** Stage the specific paths you changed.
- **Never commit secrets.** `.env` is ignored; `.env.example` documents keys.
- A change to `CYPHIX_SHARED` is a change to three apps: typecheck web AND
  mobile before committing it.
- Verify the push landed (`git fetch && git log origin/<branch> -1`).
- If a push is genuinely unwanted for a specific change, **say so explicitly
  and explain why** — do not silently skip it.

### 6.4 What "verified" is allowed to mean

`tsc --noEmit`, a successful `expo export` and `expo-doctor` prove the code is
**well-formed**. They do not prove it works: dead tap targets, elements
positioned off-screen, layouts measured mid-rotation and animations running at
the wrong speed all pass every one of them. Say "typechecks and bundles", and
keep the feature `🔬` in `PARITY.md`, until a human has touched it on a device.
